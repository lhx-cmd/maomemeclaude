# TODO2: 修复奇怪音频与用户猫素材优先级

## 原始目标

解决当前生成结果中的两个问题：

1. 视频里会出现奇怪的声音。
2. 用户上传了猫 meme 视频素材，但最终分镜没有优先采用用户提供的素材。

## 任务背景

当前现象更像是两条链路同时失控：

- 音频链路：视频合成阶段可能默认继承猫 meme motion 原视频里的音轨。很多素材即使视觉上是“猫动作素材”，内部也可能带有环境声、人声、噪声或残留 BGM，导致最终视频出现与剧情无关的奇怪声音。
- 用户素材链路：上传素材可能因为文件名清洗、扩展名丢失、类型识别不足，没被稳定识别为猫 motion；即使识别成功，后续分镜生成、多猫角色选择或 dialogue motion 分配也可能用素材库里的默认猫动作覆盖用户上传素材。

本任务目标不是扩大素材能力，而是先把“默认不漏奇怪原声”和“用户上传猫 meme 优先进入分镜/渲染”这两件事做稳定。

## 执行步骤

1. 定位音频入口
   - 检查视频合成中对 cat motion 原音、场景音频、音效库、旁白/字幕音频的选择逻辑。
   - 找出默认继承素材原音的位置，并补充回归测试覆盖。

2. 建立默认静音策略
   - 默认情况下，猫 motion 只作为画面素材使用，不自动继承原视频音轨。
   - 只有当分镜脚本显式声明需要使用某个音频源时，才允许合成该音频。
   - 没有显式音频时，场景使用静音轨，避免 FFmpeg 输出不稳定或串入旧音轨。

3. 明确音频字段语义
   - 区分 `motion video` 和 `audio asset`。
   - 保留未来可扩展字段，例如 `audio_source`、`audio_muted`、`use_motion_audio`，但第一版以“默认静音、显式才播放”为准。
   - 删除或忽略不可靠的隐式原声继承路径。

4. 修复上传素材命名与类型识别
   - 检查上传猫 meme 视频的保存逻辑，确保中文文件名或特殊文件名被清洗后仍保留真实扩展名。
   - 对已无扩展名或扩展名异常的上传素材，增加 MIME/ffprobe/Pillow fallback 识别。
   - 让 `describe_user_materials` 和 `match_user_materials` 能稳定识别上传视频为 cat motion 候选。

5. 强化用户猫素材优先级
   - 在素材匹配、分镜生成提示和角色 motion 分配中，把用户上传 cat motion 标为优先候选。
   - 当分镜需要猫角色动作时，优先从用户上传 cat motion 中选择。
   - 多猫分镜中允许用户素材作为其中一个角色，但不能被后续角色规划无声覆盖。

6. 防止后续节点覆盖用户选择
   - 检查 storyboard 后处理、dialogue 角色分配、HyperFrames 局部调整和 FFmpeg compose plan。
   - 如果 scene/dialogue 已绑定用户 motion，后续节点只能在明确冲突或用户指令要求时替换。
   - 在预览数据中保留素材来源标识，便于确认是否真的使用了用户素材。

7. 整理音频素材索引影响
   - 确认从猫 meme 视频抽出的音频素材不会被自动当作默认背景音或场景音。
   - 音频索引只作为显式音效/情绪音频候选，不参与默认猫 motion 渲染。

8. 补充测试与验证
   - 增加单元测试覆盖默认静音、显式音频、中文文件名上传、无扩展名视频识别、用户 cat motion 优先级和后处理不覆盖。
   - 用 `ffprobe` 检查生成片段音轨来源。
   - 运行 `python3 -m unittest discover -v` 和 `python3 -m py_compile server.py agent/*.py`。

## 预期结果

- 默认生成视频不再随机带入猫 meme 原视频里的奇怪声音。
- 只有脚本或用户指令明确要求音频时，才会加入对应音频素材。
- 用户上传的猫 meme 视频会被稳定识别为 cat motion。
- 分镜脚本和最终视频会优先使用用户上传猫素材，而不是被默认素材库猫动作替换。
- 前端预览能看到素材来源，方便判断“是否使用了上传素材”。

## 验收标准

- 上传中文名或特殊文件名的 `.mp4` 猫 meme 后，后端保存结果仍可识别为视频素材。
- 分镜素材匹配结果中，用户上传猫 meme 视频进入 cat motion 候选，并优先于内置素材。
- 生成的 storyboard 中，至少需要猫 motion 的核心分镜优先绑定用户上传素材。
- 多猫角色分配不会把已绑定的用户 motion 静默替换为内置 motion。
- 默认场景不继承 cat motion 原音；最终视频不出现未被脚本显式选择的原素材声音。
- 显式选择音频素材时，最终视频仍能正常带音频。
- 所有新增/修改测试通过，Python 编译检查通过。

## 执行结果

已完成实现：

- 视频合成默认不再继承猫 motion 原视频音轨；只有 scene 显式设置 `use_motion_audio` 且未静音时才使用 motion 原音，否则生成静音轨。
- 上传素材保存时保留真实扩展名，修复中文文件名被 `secure_filename` 清洗成 `mp4` 后丢失 `.mp4` 后缀的问题。
- 用户素材描述和素材匹配支持无后缀的旧上传视频路径，例如 `session_mat_mp4`，并默认把用户上传视频作为 cat motion 候选。
- 分镜生成在匹配到用户 cat motion 后，会把它绑定到可见 dialogue，并标记 `cat_motion_source/motion_source=user`。
- 多猫角色规划和兜底分配不会覆盖已绑定的用户上传 motion。
- API 序列化保留 cat motion 来源，前端分镜预览中显示“用户素材”标识。

验证结果：

- `python3 -m unittest discover -v`：124 个测试通过。
- `python3 -m py_compile server.py agent/*.py`：通过。
- 相关定向测试：68 个测试通过。
