# TODO3: 将自然语言分镜调整升级为视觉理解 Agent

## 原始目标

把当前“自然语言调整分镜”模块升级为一个视觉理解 Agent：它不仅能读懂用户明确指令，也能理解“这只猫太突兀”“这个画面不自然”“这里重新编排一下”这类模糊反馈，定位用户要求的分镜、角色、贴纸、字幕、背景或音频问题，修改分镜脚本，并确保修改能应用到后续视频生成。

## 任务背景

当前自然语言调整主要依赖分镜脚本文本和规则化字段做改写。它看不到实际画面，也无法基于渲染预览判断“右侧猫”“左边贴纸”“画面太空”“猫太大”“字幕挡脸”等视觉问题。因此用户提出模糊或画面指代类反馈时，Agent 容易只生成一段解释，或者改了不可见字段，最终视频没有发生变化。

要解决这个问题，需要在现有 LangGraph 调整链路里局部加入视觉观察和验证能力：先把相关分镜渲染成可供模型理解的预览图，再让 Agent 结合用户指令、分镜 JSON、素材索引和画面截图生成结构化编辑计划，最后把编辑计划落到真正参与视频合成的 storyboard 字段上。

## 执行步骤

1. 梳理当前调整链路
   - 检查自然语言调整接口、LangGraph 编辑节点、分镜脚本结构、视频合成读取字段，以及前端展示字段。
   - 明确哪些字段会影响最终视频，例如猫 motion、角色锚点、位置、缩放、贴纸、字幕、背景、音频和生成缓存状态。

2. 新增视觉观察层
   - 为指定分镜生成轻量级预览图，优先复用已有预览或局部渲染能力，避免每次都完整生成视频。
   - 将预览图、分镜 JSON、角色/素材描述、用户原始指令一起组织成视觉理解输入。
   - 当用户没有明确分镜编号时，先用文本线索筛选候选分镜，再只检查少量相关分镜。

3. 接入视觉编辑 LangGraph
   - 在现有编辑 workflow 中增加粗粒度节点：`select_targets -> inspect_visuals -> plan_visual_edit -> apply_visual_edit -> validate_visual_edit`。
   - 对“删除分镜 2 的音频”这类精确命令继续走快速确定性路径。
   - 对“右侧锚不合适”“画面不自然”“猫太突兀”等模糊视觉命令走视觉理解路径。

4. 设计 Agent 可用工具
   - 读取指定分镜完整 JSON。
   - 读取可用猫 motion、贴纸、背景、音频的描述索引。
   - 查询或更换角色 motion。
   - 修改角色位置、缩放、锚点、层级和左右布局。
   - 删除、替换或重排贴纸和道具。
   - 修改主题字幕、带星号场景说明、角色台词和底部旁白。
   - 静音或替换指定分镜音频。
   - 标记旧视频失效，确保后续生成读取修改后的 storyboard。

5. 约束视觉编辑输出
   - 让模型只输出结构化 edit plan，不直接写自由文本。
   - 每条 edit operation 必须包含 `scene_index`、`target`、`field`、`old_value`、`new_value`、`reason` 和 `confidence`。
   - 默认做最小必要修改，避免一次反馈导致整个分镜被重写。
   - 如果视觉证据不足，返回需要确认的问题，而不是生成无效修改。

6. 落地修改并保证生效
   - 将 edit plan 转换为实际 storyboard 字段变更。
   - 对新增的视觉控制字段补齐视频合成读取逻辑，例如角色局部缩放、锚点覆盖、贴纸删除、音频静音等。
   - 调整后清空或失效旧的 `video_path`，避免前端继续播放旧视频。
   - API 响应返回变更摘要和更新后的 storyboard，方便前端展示差异。

7. 增加视觉验证
   - 对被修改分镜重新生成预览图。
   - 检查结构化字段是否真的发生变化。
   - 对可规则验证的问题做自动断言，例如删除音频后该分镜不再使用音频，缩小猫后 scale 变小，替换 motion 后路径变化。
   - 如果编辑计划是 no-op，直接返回失败原因，避免用户误以为修改成功。

8. 性能与稳定性控制
   - 按 storyboard hash 缓存分镜预览图。
   - 限制单次视觉检查的分镜数量和图片尺寸。
   - VLM 失败时回退到文本编辑路径，并在响应中说明未完成视觉校验。
   - 保持现有 public API 尽量不变，只扩展内部 workflow 和响应中的诊断信息。

9. 测试与回归
   - 单元测试覆盖目标分镜选择、视觉 edit plan 解析、字段落地、旧视频失效、no-op 检测和精确命令快速路径。
   - API 测试覆盖自然语言调整后 storyboard 发生变化，后续视频生成使用修改后的 storyboard。
   - 编译和全量测试通过后再交付。

## 预期结果

用户可以用更自然、更模糊的语言调整分镜，例如“分镜 4 右边这只猫不合适，换一个更像领导的”“这段画面太空了，重新编排一下”“这只猫挡住字幕了，处理一下”。系统会先理解用户指向的画面元素，再生成可执行修改，并把修改写入真正参与视频合成的分镜数据。

调整完成后，用户能在分镜脚本或变更摘要中看到变化；重新生成视频时，画面、字幕、音频或素材选择会按调整后的结果呈现。

## 验收标准

- 输入“分镜 4 的右侧锚选择不合适，要求更换”后，系统能定位分镜 4 右侧角色，并修改对应角色 motion 或锚点，而不是只改解释文本。
- 输入“分镜 5 左边那只猫太大了，缩小它”后，storyboard 中对应角色的 scale 或布局覆盖字段发生变化，后续视频里左侧猫实际变小。
- 输入“删除分镜 2 的音频”后，分镜 2 的音频字段被清空或静音，后续视频生成不再混入该分镜原音频。
- 输入“这个贴纸没意义，删掉”后，视觉 Agent 能结合预览图和分镜内容删除或替换无关贴纸。
- 模糊指令没有明确分镜号时，系统能根据文本和视觉线索选择候选分镜，并给出修改摘要。
- 如果模型生成的 edit plan 没有造成任何 storyboard 字段变化，接口返回可诊断失败信息，不展示“调整成功”。
- 调整接口会失效旧视频路径，后续 `/api/generate-video-stream` 使用修改后的 storyboard。
- 现有精确自然语言调整能力不退化。
- 验证命令通过：`python3 -m unittest discover -v`。
- 编译检查通过：`python3 -m py_compile server.py agent/*.py`。
